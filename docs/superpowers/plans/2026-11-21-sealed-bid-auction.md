# Sealed-Bid Auction on Canton — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Tasks inside a wave run in **parallel**, each in its own git worktree.

**Goal:** A sealed-bid, first-price auction app on Canton, with its DAR deployed on the Splice LocalNet
validators. Automated tests prove the 5-user end-to-end flow on the live network.

**Architecture:**
- **Ledger:** Daml templates enforce the rules and privacy. They use sub-transaction privacy, bind each
  close to the auction's own invitations (lineage), and use no contract keys.
- **Backend:** TypeScript. It talks to each user's participant over JSON Ledger API v2, always with that
  user's own JWT.
- **UI:** React, calling the backend.
- **Ops scripts:** deploy the DAR to every participant and provision the 5 users.
- **Tests:** Daml Script, backend unit tests, a live LocalNet E2E suite, and Playwright.

**Tech Stack:**
- Daml SDK 3.6.3 via `dpm`.
- Splice LocalNet 0.9.4 (Canton 3.6.4), from cn-quickstart commit `374f2d6`, started with
  `make start-localnet`.
- Node 24 + TypeScript (npm workspaces): Fastify, `openapi-typescript` + `openapi-fetch`, `jose`, Vitest,
  `tsx`.
- React 18 + Vite; Playwright.

**Spec:** `docs/superpowers/specs/2026-11-21-sealed-bid-auction-design.md` (research:
`docs/canton-research.md`)

## Global Constraints

- **Versions:**
  - Daml `sdk-version: 3.6.3`.
  - LocalNet `SPLICE_VERSION=0.9.4`.
  - cn-quickstart pinned at `374f2d6`.
  - Pin them together. Don't pass `--target`; record the built LF version.
- **Packages:** `sealed-auction` (uploaded) and `sealed-auction-tests` (never uploaded). Module
  `SealedAuction.Auction`. Template ids use the package-name form
  `#sealed-auction:SealedAuction.Auction:<Template>`.
- **Daml freeze:** after the first live deploy, any Daml change requires `make localnet-reset` (clean +
  up + deploy + provision). Never re-upload a changed package under the same version.
- **JSON API:**
  - Types are generated from the vendored Canton v3.6.4 `openapi.yaml`.
  - Commands use `transactionFormat` with `TRANSACTION_SHAPE_LEDGER_EFFECTS`.
  - ACS reads pass an explicit `activeAtOffset`.
  - Updates calls use `updateFormat` and `beginExclusive`.
- **LocalNet JWT:** HS256, secret `unsafe`, `aud=https://canton.network.global`, `sub=<ledger user id>`.
  The admin user is `ledger-api-user`.
- **Topology:** lives in `config/topology.json`. Code never hardcodes ports. Ledger user id = party
  hint = lower-case display name.

  | User | Interim (MVP) | Target (Q2 = B) |
  |---|---|---|
  | auctioneer | app-provider `:3975` | app-provider |
  | alice | app-user `:2975` | app-user |
  | bob | app-user | `bidder-bob` (port from Task 4) |
  | carol | app-user | `bidder-carol` (port from Task 4) |
  | dave (outsider) | app-user | app-user |
  | auditor (tests only) | `CanReadAsAnyParty` on sv and on every bidder node | same |
- **Rights:**
  - Every user path uses that user's own token, which grants `CanActAs` + `CanReadAs` on its own party
    only.
  - The admin token is used only in ops scripts and test-only audit probes.
  - Disclosure blobs never appear in API responses or logs.
- **Business rules:** each auction has exactly **3** distinct invitees (constant `inviteeCount = 3`). The
  auctioneer can never be an invitee.
- **Error ids:** Daml failures carry stable ids with the prefix `SA_`.
  - They are raised with `failWithStatus` if Task 3 shows it works on 3.6.3, otherwise with
    `assertMsg "SA_<ID>: …"`.
  - The client reads the id from the structured error.
- **Ports:** backend `8787`; Vite `5173`, which proxies `/api` to `8787`.
- **Login:** demo login uses per-user passwords from `config/credentials.json`, generated by provision.
- **Gitignored:** `config/parties.json`, `config/credentials.json`, `.localnet/`, `.daml/`,
  `node_modules`, test output.

## Review Focus

1. **Bad invitee lists.**
   - Inputs: unknown name, duplicate, the auctioneer, the outsider as bidder, 2 or 4 names, empty item.
   - Expected: 400 before any ledger call.
   - Tests: Task 7 `createAuction rejects bad invitee lists`. Ledger backstop: Task 1
     `test_ensureInvariants`.
2. **Malformed amounts.**
   - Inputs: `0`, `-5`, `abc`, `1e3`, more than 10 decimal places, empty.
   - Expected: 400.
   - Tests: Task 7 `placeBid rejects malformed amounts`. Ledger backstop: Task 1
     `test_nonPositiveBidRejected`.
3. **A bid that commits between the close's ACS read and its submit, or two concurrent closes.**
   - Expected: the close retries on fresh state; the loser gets 409 `CLOSE_CONFLICT`, never a 5xx.
   - Tests: Task 10 `close retries when a bid lands mid-close` and `competing closes`.
4. **Double actions** (double-clicked close, repeated bid).
   - Expected: 409 `AUCTION_CLOSED` / `ALREADY_BID`. The backend derives `ALREADY_BID` by checking the
     caller's own `Bid`/`AuctionOutcome` for that auction.
   - Tests: Task 7 `error mapping`; Task 10 `alice cannot bid twice`.
5. **Re-runs and restarts** (re-running deploy or provision; partial provision where the party exists
   but the user is missing; stale `parties.json`; LocalNet restart).
   - Expected: idempotent repair.
   - Test: Task 6 `provision is idempotent and repairs partial and stale state`.

```
        ──► MVP / demo ready on the interim topology

```

**Rules for parallel agents:**
- **Frozen interfaces.** Wave 0 freezes every cross-track interface: the Daml field names, the
  `LedgerClient` TypeScript interface, the REST contract, and the `topology.json` schema. Changing any of
  them goes back to the lead.
- **Shared LocalNet.** Only tracks B and C touch the live LocalNet in Wave 1.
  - Track B adds validators additively. It never runs stop/clean on the shared LocalNet without the
    lead.
  - Track C's live tests use unique party hints per run (`t<runId>-alice`).
- **Dependencies.** Wave 0 installs them. An agent that adds one says so in its report, and the lead
  re-runs `npm install` at merge.
- **End of wave.** The lead merges the worktrees and runs `make test`.

**MVP critical path:** Task 0 → Task 1 → Task 9 → Task 10. Task 9 also needs Task 3 and Tasks 5, 6
and 7.

**Interfaces (frozen; the backend relies on these JSON field names):**
```haskell
inviteeCount : Int = 3
data BidResult = Won with amountOwed : Decimal | Lost   deriving (Eq, Show)

template AuctioneerRole with auctioneer : Party                                    -- signatory auctioneer
  nonconsuming choice CreateAuction : ContractId Auction
    with auctionId : Text; item : Text; invitees : [Party]   controller auctioneer
    -- creates the invitations first, then the Auction recording their cids
template Auction with auctioneer : Party; auctionId, item : Text; invitees : [Party]; invitations : [ContractId AuctionInvitation]
  -- signatory auctioneer; NO observers; ensure item /= "", length (dedup invitees) == inviteeCount == length invitees, auctioneer `notElem` invitees
  choice Auction_Close : ContractId AuctionResult
    with bids : [ContractId Bid]; openInvitations : [ContractId AuctionInvitation]   controller auctioneer
template AuctionInvitation with auctioneer, bidder : Party; auctionId, item : Text      -- signatory auctioneer; observer bidder
  choice PlaceBid : ContractId Bid with amount : Decimal   controller bidder           -- consuming
  choice Invitation_Expire : ContractId NoBidNotice        controller auctioneer
template Bid with auctioneer, bidder : Party; invitationCid : ContractId AuctionInvitation; auctionId, item : Text; amount : Decimal; submittedAt : Time
  -- signatory bidder, auctioneer
  choice Bid_Conclude : ContractId AuctionOutcome with won : Bool   controller auctioneer
template AuctionOutcome with auctioneer, bidder : Party; auctionId, item : Text; bidAmount : Decimal; result : BidResult  -- signatory auctioneer, bidder
template NoBidNotice    with auctioneer, bidder : Party; auctionId, item : Text                                   -- signatory auctioneer; observer bidder
template AuctionResult  with auctioneer : Party; auctionId, item : Text; winner : Optional Party; price : Optional Decimal; bids : [(Party, Decimal)]  -- signatory auctioneer
```
